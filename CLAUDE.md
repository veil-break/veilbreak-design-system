# veilbreak-design-system guidance

`AGENTS.md` is a symlink to this file, so every coding agent reads the same rules. This repository
(`veil-break/veilbreak-design-system`) is **public**: commit nothing private to it (no private repository contents, no
owner personal paths, no Asset Store content, no tokens or secrets). Cross-repository rules (ownership, GUIDs, pins, landing
order) live in the workspace hub's `CLAUDE.md`; `SOUL.md` is the shared agent soul. In a workspace checkout, `vb agents sync`
(run from the hub) links `SOUL.md`, `.claude/skills` and `.claude/agents` here. They are ignored by `.gitignore`.

## What this repository owns

Shared presentation for the games, one Unity package per folder under `packages/` (see the [README](README.md)):

| package | rule |
| --- | --- |
| `com.veilbreak.gui` | The sole token authority: `Tokens~/tokens.json` (plus `fluid.json`, `motion.json`, `components.json`). Controls, composites, views, hud, world labels, navigation. Unity 6000.3. |
| `com.veilbreak.feedback` | Cue catalog (`CueCatalog`), `CueStage` (draws catalogue cues through pooled sinks), telegraphs, ground marks, screen impacts, battle surfaces, URP effects. URP 17.3. |
| `com.veilbreak.rendering` | URP render features, volume overrides and shaders (`Glitch`, `LensStreaks`, `VisorLens`, `MaterialPaint`). URP 17.3 baseline. |
| `com.veilbreak.environment` | The veil street: `SegmentStreamer`, `ISegmentPlan` / `SegmentDescriptor` / `IStreetKit`, namespace `Veilbreak.Cityscape`. |
| `com.veilbreak.branding` | Intro splash and the slash-cut mark. |
| `com.veilbreak.ar-hud` | The HUD framework main hosts every screen with, an adapter over `gui`. The only package on Unity 7000.0. |
| `com.veilbreak.presentation` | Entry package: declares the others at tested versions; no assets, no assembly. |

Games own rules, scenes, presenters and adapters; they only bind plain view models and map events to cues. Character
identity and kits belong to the characters repository.

## Rules

- **Tokens.** Edit `packages/com.veilbreak.gui/Tokens~/tokens.json`, never `Runtime/Styles/Tokens.uss`,
  `TokensContrast.uss`, `Runtime/Core/VbTokens.cs` or `Documentation~/tokens.md` (generated by `Tools~/tokens.py`). Motion
  recipes come from `Tokens~/motion.json` through `Tools~/motion.py` (`MotionRecipes.cs`, `Tools~/web/motion-recipes.js`);
  the fluid scale from `Tokens~/fluid.json` through `Tools~/fluid.py`. Guide: [docs/tokens.md](docs/tokens.md).
- **Authoring editor.** Author and reserialize shared assets (prefabs, materials, scenes, `.asset`, `.meta`) in 6000.3.
  Never open a producer package with a 7000.0 editor: it rewrites 6000.3 assets. Only `ar-hud` is authored in 7000.0.
- **Baseline.** Shaders, render features and feedback URP code target 6000.3 with URP 17.3. A 17.7 difference goes behind
  `versionDefines` in the asmdef (none is needed today).
- **GUIDs.** Keep every `.meta`; moved files carry theirs. New files get stable metas from `Tools~/metas.py`.
- **Real names.** Use the class names in the code (`CueStage`, `ISegmentPlan`, `VisorLens`); grep before writing one.
- **Environment.** The `Veilbreak.Cityscape` namespace is deliberate (`Veilbreak.Environment` would hide `System.Environment`).
  `ISegmentPlan.Resolve(index)` must be pure.
- **Binaries.** Plain git blobs here (no LFS), so a git package resolves without git-lfs; keep them small.
- **Releases.** A package change bumps its `package.json` version and CHANGELOG; the hub pins the full commit in the game specs.
- **Public repository.** No private repository contents, Asset Store content, owner personal paths or secrets in code, docs or comments. The generated issue forms and `.claude/settings.json` name the workspace hub because the hub's `vb roadmap sync` writes them.

## Verification

From the repository root (CI is `.github/workflows/deploy-pages.yml`):

```sh
uv sync --locked
uv run --frozen ruff check .
uv run --frozen ruff format --check .
uv run --frozen python packages/com.veilbreak.gui/Tools~/tokens.py --check
uv run --frozen python packages/com.veilbreak.gui/Tools~/motion.py --check
uv run --frozen python packages/com.veilbreak.gui/Tools~/fluid.py --check
uv run --frozen python packages/com.veilbreak.gui/Tools~/screen_kit.py --check
uv run --frozen python packages/com.veilbreak.gui/Tools~/samples.py --check
uv run --frozen python packages/com.veilbreak.gui/Tools~/metas.py --check
uv run --frozen python packages/com.veilbreak.ar-hud/Tools~/themes.py --check
uv run --frozen python packages/com.veilbreak.branding/Tools~/logo.py --check
dotnet run --project packages/com.veilbreak.ar-hud/Tests~/InputChecks/Veilbreak.ARHud.InputChecks.csproj
```

Unity checks (EditMode and PlayMode in a consumer or a throwaway 6000.3 project) are separate; never report a headless
run as editor or device evidence.
