# Feedback guide

`com.veilbreak.feedback` (assemblies `Veilbreak.Feedback`, `Veilbreak.Feedback.URP`, `Veilbreak.Feedback.UI`; Unity 6000.3,
URP 17.3) draws combat feedback from events the game has already confirmed. It never reads game state and never feeds
the simulation: the game maps its events to cues, calls the pooled sinks and advances them with its own delta. This guide
lists what exists; each type's XML comment has the detail. Everything below is in `packages/com.veilbreak.feedback/Runtime`.

## The call surface

| step | call |
| --- | --- |
| Build the sinks | `EffectEmitters.Initialize(additive, alpha, high)`, `GroundMarks`, `LightFlashes.Initialize(capacity)`, `AudioVoices`; materials come from `CueCatalog` (`additive`, `alpha`, `marks`, `telegraph`, `hitFlash`) |
| Make the stage | `new CueStage { Emitters, Marks, Flashes, Voices }` (any may be null), then set `Shake`, `Pulsed` and `ReducedFlashes` from the host |
| Per mapped event | `stage.Play(cue, fallbackRoutine, call, groundPoint)` where `cue = catalog.Find(key, ...)` |
| Heavy moment | `stage.Punch(at, colour, strength, camera)` |
| Marked body | `CueStage.Reticle(batch, local, size, colour, time)` |
| Each frame | `emitters.Advance(simDelta)`, `marks.Advance`, `flashes.Advance`, `DecalPool.Tick(now)`, `ScreenImpacts.Advance(unscaledDelta)` |

`Play` runs the particles (budgeted), then the ground mark, the light flash (skipped under `ReducedFlashes`), the shake and the
sound. Event mapping, colours and strengths stay in the game. Samples: `Samples~/Integration.md` and `Samples~/MinimalConsumer`.

## CueCatalog and CueStage

`CueCatalog` (a `ScriptableObject`, menu *Veilbreak/Feedback catalog*) holds `CueCatalog.Cue` rows. A key is an event kind
(`hit`), a skill shape (`burst`) or a per-skill row (`skill:aria.basic`); `Find(first, second, third)` returns the first
row that exists, most specific first. `CueStage` is a class, not an enum: it has no list of stages of its own.

A `Cue` row:

| field | meaning |
| --- | --- |
| `routine` | an `EffectRoutine`; the cue's routine wins over the caller's fallback |
| `magnitude`, `tint` | scales the call (1 normal, above 1 heavy); a tint with alpha above zero replaces the event colour |
| `priority` | 2 and above always plays; lower pieces are dropped when the particle budget is spent |
| `shake` | 0 to 1, raised through `CueStage.Shake` |
| `pulse` | a flash-volume weight, raised through `CueStage.Pulsed` |
| `light`, `mark`, `markSize` | peak point-light intensity (0 for none); a `MarkKind` and its size |
| `sound`, `volume` | an `AudioClip` played through `AudioVoices`, panned by `ground.x / PanWidth` |
| `size`, `duration` | serialized fields (defaults 0.08 and 0.25) that `CueStage.Play` does not read; a host may use them for its own `FeedbackRequest`s |

`EffectRoutine` values (stored as integers in cue assets: add new ones at the end): `None`, `Impact`, `Explosion`, `Muzzle`,
`Beam`, `Cone`, `Zone`, `Dash`, `Wall`, `Mend`, `Ward`, `Charge`, `Portal`, `Pulse`, `Reward`, `Swap`, `Splash`.
`MarkKind`: `None`, `Scorch`, `Crack`.

### Camera shake

There are no named shake presets. A cue's `shake` is a number from 0 to 1 and `CueStage.Shake` is an `Action<float>` the
host sets; the host scales it onto its own camera rig and owns the Reduced Motion policy. `Punch` does not shake: shake and
any HUD jolt stay with the host. `pulse` and the `CinematicPulse` volume are the flash side of the same hook.

## Particles, marks, lights and sound

- `EffectEmitters`: pooled particle layers `Sparks`, `Glow`, `Embers`, `Flame`, `Smoke`, `Rings`, `Shards`, `Plus`, `Splash`,
  `Flares` over the `FxTile` atlas (`Runtime/Textures/T_FxAtlas.png`; tiles `Glow` ... `Band`, regenerated by `Tools~/fx_atlas.py`).
  Budget per frame: `HighBudget` 560 particles, `LowBudget` 190. `Play(routine, FxCall, priority)`, `Emit`, `Drift(metres)`
  (slides the effect space with a moving road), plus `Smolder`, `Trail`, `Mote`, `Curtain` and `Shell` accents.
- `GroundMarks`: scorch and crack marks in a ring buffer (`HighCapacity` 96, `LowCapacity` 32) that fade over their life.
  `QuadBatch` draws any per-frame ground quads (one draw call).
- `LightFlashes`: pooled point lights, capacity set by the tier (0 turns flashes off), oldest reused.
- `AudioVoices`: 8 two-dimensional voices (`Voices`), repeats of one clip inside `Repeat` (0.06 s) dropped, a full pool steals
  the quietest lower-priority voice, `Volume` is the host's effects level. Clips in `Runtime/Audio` (`A_Tap`, `A_Zap`,
  `A_Whoosh`, `A_Charge`, `A_Heal`, `A_Shield`, `A_Spawn`, `A_Swap`, `A_Splash`, `A_Warning`, `A_Stinger_Wave`,
  `A_Stinger_Boss`) come from `Tools~/sounds.py`.
- `FeedbackPool`: the older bounded line and particle pool driven by `FeedbackRequest`.

## Telegraphs

`GroundTelegraphs` draws up to `Capacity` (64) ground projections per frame: `Initialize(material)` with `Telegraph.shader`,
then `Begin()`, `Draw(request)` in priority order, `End()`. A `TelegraphRequest` has a `TelegraphShape` (`Circle`, `Cone`,
`Segment`), a `TelegraphPhase` (`Preview`, `Windup`, `Active`, `Residue`), `origin`/`end`, `radius`/`halfWidth`/`angle`
(cone full angle in degrees), `colour`, `progress`, `hostile` and `curtain` (metres of light curtain along the outline).
Footprints of one side merge (up to `Neighbours` = 8 overlapping), hostile and friendly never do. `TelegraphGeometry` holds the
same signed-distance maths as the shader (`Distance`, `Inside`, `Outline`, `Union`) so a test can compare the drawn footprint
with the simulation's hit area. `CurtainBatch` builds vertical light curtains in one mesh; its shader reads the global
`_CurtainPhase` set by `CurtainBatch.Phase(time)` (0 under Reduced Motion).

## Battle surfaces (URP)

- `DecalPool`: `Initialize(capacity)` (`DefaultCapacity` 128, the cap for the quality tier), `Place(material, at, size, life)`.
  Decals project straight down (`Depth` 3 m), fade over the last third of their life, the oldest goes first at the cap;
  `DrawDistance` defaults to 42 m. `Clock` (default `Time.time`) stamps each decal when placed and `Tick(now)` fades and retires them.
- `SurfaceIndicators`: plan lines projected through world depth. Construct with a URP decal material template, a segment cap
  (`DefaultCapacity` 256) and an optional four-slot palette; set `Top`/`Bottom`; `Begin()`, `Draw(points, width, loop, colour)`, `End()`.
- `PooledEffect.Create(prefab, parent, release)`: a one-shot prefab instance that releases itself to the host's `ObjectPool`
  from the particle stop callback (`FallbackSeconds` 2 if it never stops).

## Whole-screen effects

- `ScreenImpacts.Push(viewport, colour, strength)` and `Advance(unscaledDelta)`; up to `Capacity` (4) at once, each `Seconds`
  (0.55 s) at strength 1. Strength is about 0.2 for a heavy hit and 1 for a boss slam. Settings: `Motion` (0 under Reduced
  Motion drops refraction, punch and split), `Flash` (0 under Reduced Flashes drops the vignette and brightening), `Gain`.
- `CinematicPulseFeature` + the `CinematicPulse` volume override (`strength`): register the feature in the URP renderer and
  assign `CinematicPulse.shader`; it renders the strongest impacts even while no pulse volume is active.
- `OverlayBlurFeature` + `OverlayBlur` (`strength`, `downsample` 1 to 4): world-only blur behind modal layers.
- `GammaUiFeature` + `GammaUiPanel`: composites gamma-authored UI over a linear world; one active `UIDocument` and game camera,
  no XR. Budget the extra full-resolution surface on hardware.
- Pass events: `CinematicPulseFeature` runs before URP's post-processing, `OverlayBlurFeature` just before the end of it (`AfterRenderingPostProcessing` minus one) and `GammaUiFeature` after it, so the order is pulse, world post-processing, overlay blur, gamma UI.

## Projected readouts

`ProjectedReadouts` (`Veilbreak.Feedback.UI`) is the 1.0 API over `WorldLayer` in `com.veilbreak.gui`; new code uses `WorldLayer`
directly.

## Rules

- Reduced Motion and Reduced Flashes are host settings: set `CueStage.ReducedFlashes`, `ScreenImpacts.Motion`/`Flash`, and pass 0
  to `CurtainBatch.Phase`.
- Feedback is presentation only. Nothing here may be read by the simulation.
- URP code targets URP 17.3; the package has no version-specific code paths today.
