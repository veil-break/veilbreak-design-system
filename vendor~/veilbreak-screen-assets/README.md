# veilbreak — menu and courtyard asset pack

created 11 october 2026 from the supplied specification v2 and its two concept sketches.

this folder is the original pack (34 meshes, no uvs, its own `metadata/tokens.json`). the improved copies the game consumes (46 meshes with planar uvs, token-aligned colours, no separate tokens file) live under `unity/Assets/_Veilbreak/` and are regenerated by `vb screens build|images|package` (`assets/src/veilbreak_assets/screens/`, which reads this pack's `art/`); the descriptions below refer to the original pack.

## contents

- `art/`: empty menu and courtyard plates; eight individual alpha fighter illustrations; optional sky, skyline and foreground menu layers; asphalt color texture.
- `ui/`: individual svg icons, cut-corner frames, ability states, selection platforms, team marks, targeting examples and floor decals. no baked text or numbers.
- `models/`: 34 editable gltf 2.0 binary environment meshes, in metres with y up and ground-centred pivots. all materials embedded; no external dependencies.
- `metadata/`: semantic tokens, per-file sizes and checksums, image dimensions, mesh statistics and import notes. roster data is not kept here; it comes from the characters projection in `veil-break/characters` `exports/`.
- the pack's own generator scripts (`source/build_assets.py`, `source/package_assets.py`) were retired in favour of the improved generator above; `git show 26b8452:assets/source-packs/veilbreak-screen-assets/source/build_assets.py` recovers them.

## what is ready

the raster art and vector screen kit are usable as presentation assets. all eight character illustrations are new visual proposals, not canonical dossier replacements. the original three-woman sketch does not define the identities of the full roster.

environment meshes are low-poly starter art with material colors and separate named parts. they are not high-detail reconstructions of the illustration. all four destructible families have intact, cracked, broken and rubble variants: concrete planter, signal kiosk, utility barricade and vehicle barricade. the two anchors are permanent. facade, damaged facade, roof modules, lamps, trees, asphalt, sidewalk, curb, embankment, water and skyline blocks complete the environment starter kit.

this pack does not include rigged/animated fighters, audio, baked lightmaps, authored lod chains or unity prefabs. those remain production work. no game repository was changed, and the assets have not been tested in the live client. the courtyard plate is illustrative; it is not collision geometry or a scale-accurate projection.

## menu assembly

the simplest composition uses `menu-boulevard.png` as the full-screen backdrop. place 1–4 fighter pngs above it using their bottom-centre pivots, add platform vectors beneath their feet, and put navigation and inspector controls above them. the raster plates are 1672 × 941; use cover sizing with safe-area checks rather than stretching.

`menu-sky`, `menu-skyline` and `menu-foreground` are optional separately generated parallax assets; they are not pixel-matched extractions from the baked plate. compose them with a ground plane using the asphalt material. keep any parallax small and disable it for reduced motion. use the baked plate for the low-cost fallback.

take role and tier from the characters projection in `veil-break/characters` `exports/`, not from this pack. aria, aegis and echo use rare blue, not the violet rare label in the original sketch. left navigation is team, rifts, automation, studio, replays. render wallet/connection status above, inspector to the right and a single battle action below. names, currencies and connection values remain runtime text.

## level assembly

use `court-floor-40x62.glb` at the origin as a visual floor. its bounds are x ±20 m and z ±31 m. the safe area is x ±8 m, z ±12 m; spawn rows are z ±27 m. place buildings outside that rectangle. floor units do not validate the perspective image's scale.

bind each cover instance to the existing authoritative map id, transform, footprint, material and structure points. the supplied pdf does not enumerate the coordinates of all 21 cover objects, so no guessed prop layout is shipped. scale or re-author starter meshes to fit those exact footprints before gameplay use. do not derive collision from generated art. swap damage variants from simulation state; rubble must retain the intended rough-ground footprint.

canal and exterior blocks are scenery only. water mesh is a flat opaque starter material, requiring a water shader if desired. facade windows and emissive kiosk panels are separate mesh parts. these models have no uv channels; use material colors or world-space/triplanar mapping. the asphalt image is an albedo candidate; seamless repeat and physical material values are not certified, and no fabricated normal/roughness maps are included.

## vectors and runtime states

icons use a 24-unit viewbox, 1.6-unit square-cap strokes. accompany each glyph with text or an accessible name. desktop interaction targets must be at least 44 px, touch targets 48 px. cut frames use top-left and bottom-right cuts only. provided frame dimensions are design sizes: resizing a whole svg non-uniformly distorts strokes and cuts; rebuild the path from tokens at the target size or use an appropriate sliced asset importer.

ability frames cover ready, aiming, queued, windup, cooldown, insufficient power, silenced, exposed and invalid aim. they provide visual bases; countdowns, costs and blocked-state reasons are live text. keep disabled content readable.

ally marks are circles; enemy marks are diamonds. telegraph files are normalized shape examples, not collision/range masks. create exact runtime geometry from skill range, radius, angle and clipping. pressure uses crimson hatch. beam and wall are visually distinct. do not stretch the example cone into an authoritative angle.

use `metadata/tokens.json` as this pack's token record, reconcile it with the repository's central token generator, and reuse the project's poppins and tex gyre adventor fonts. font binaries are not bundled. the outlined wordmark is font-independent bespoke line art.

high contrast uses solid black panels and white text; disable decorative glow, scanlines and grids. the supplied high-contrast panel is a base; regenerate other semantic alternates from tokens. battle must have no depth of field or grain. these assets contain no baked combat glow or animation.

## import notes

- png art: srgb, straight alpha where present, clamp edges; inspect hair/weapon fringes against both light and dark surfaces. generated alpha includes semi-transparent edge pixels.
- glb: metres, y-up. use a gltf importer or convert in the art pipeline. no colliders, scripts, animation or gameplay authority are embedded.
- svg: rasterize at the destination density if the target client does not support vectors. preserve line weight and cut sizes. all text remains native ui text.
- performance: pool props and effects, instance repeated modules, and consider combining static parts after material/visibility batching. the many named parts are convenient for editing but are not a draw-call budget claim.

## provenance and verification

raster images were generated with the built-in image-generation tool using the supplied sketches as visual references. prompts are recorded in `metadata/image-prompts.json`. vectors and meshes are original procedural assets; source is included. validation checks png decoding/alpha, svg xml, glb headers/accessor bounds/triangle data and package file hashes. validation does not replace visual art review, physics parity, performance tests or engine import testing.
