# Web mirror

The Veilbreak Design System artifact is a web copy of this package. Designers and reviewers can browse the kit,
tokens, icons and guidelines there, and design agents can build screens from the same components. Everything in it is
generated by `Tools~/web/build.sh`, so this package is the only place to change the system.

No web client ships. The mirror exists so that the kit can be read, reviewed and designed with outside Unity.

## What the build writes

`Tools~/web/build.sh OUT` writes the artifact's `project/` folder to `OUT/project`. Intermediates go to
`OUT/generated`.

| Artifact path | From |
| --- | --- |
| `README.md` (the brand book) | `Documentation~/brand.md` |
| `01-hud-layout.md` … `05-platforms.md` | `Documentation~/guidelines/` |
| `tokens.json` | `Tokens~/tokens.json` |
| `fonts/` | `Runtime/Fonts/` (`.ttf`, `.otf`) |
| `components/bundle.css` | `Runtime/Styles/Gui.uss`, `Layout.uss` and `World.uss` through `uss2css.py`, after `base.css` and before `supplement.css`; first, the legacy kit's CSS renamed to `vbl-` |
| `components/bundle.js` | The legacy kit as `window.Veilbreak.Legacy`, then `kit.js` with the icons inlined (`icons_js.py`) |
| `components/index.d.ts` | `docs.py`: the kit's types, then the legacy types in `namespace Legacy` |
| `components/<Name>/README.md` | `docs.py` for the kit; `Tools~/web/legacy/components` for the kept legacy components, with a deprecation note |
| `components/<Name>/preview.html` | `previews.py` for the kit; the legacy previews, renamed to `vbl-` and `Veilbreak.Legacy` |
| `components/Cover/preview.html` | `Tools~/web/cover.html` |
| Icons asset group | `Runtime/Icons/*.svg`, uploaded as assets under their canonical names |

## How the port works

- **Styles.** `uss2css.py` ports the kit's USS mechanically, so values stay exact:
  - Class names and `--vb-*` shape properties are kept.
  - Token variables lose their prefix (`--vb-color-text` → `--text`), because the artifact compiles `tokens.json` to
    CSS under the bare names.
  - `:root` becomes `.vb-root`, and `.unity-*` becomes `.vb-u-*`.
  - Unity font files become family and weight.
  - TextCore letter-spacing (hundredths of an em) becomes `em`.
  - `-unity-text-align` becomes flex alignment.
- **Layout defaults.** `base.css` gives `.vb-root` UI Toolkit's defaults: every element a column flexbox with
  `flex-shrink: 1`.
- **Components.** `kit.js` holds React 18 ports of each component. They build the same element tree with the same
  classes. `VbShape` paints the cut polygon as SVG from the same `--vb-*` properties that `VbShape.cs` reads.
- **Previews.** Each preview card draws one component in its main states. The data comes from `Samples~/Gallery` and
  `Samples~/BattleHud`. The `BattleHUD` card is the portrait board built only from the bundle.

When you change a component in C#, change its port in `kit.js`, its README and types in `docs.py`, and its card in
`previews.py`. The build fails when an exported component has no README or preview.

## Legacy web

The artifact began as the landscape arena kit for the online Veilbreak game: 31 web components with `vb-` classes.
Twenty of them have a version in this package, and the package's versions replace them under their names. The other
eleven serve desktop and online play, which the arcade does not have:

- ConnectionPill
- ConnectionBanner
- CombatFeed
- Minimap
- NavBar
- MatchHeader
- ItemCell
- RailButton
- Timeline
- FighterPortrait
- Telegraph

They are kept, deprecated, in the *Legacy web* group:

| | Legacy | Kit |
| --- | --- | --- |
| Classes and custom properties | `vbl-` (`.vbl-btn`, `--vbl-cut`) | `vb-` |
| Namespace | All 31 components in `window.Veilbreak.Legacy` | `window.Veilbreak` |

The rename is done at build time by `(?<![A-Za-z0-9_])vb(?![A-Za-z0-9_])` → `vbl`. The legacy files in
`Tools~/web/legacy/` stay as they were published.

- The eleven are also exported at the top level, so `window.Veilbreak.Minimap` works.
- The legacy landscape board is the `LandscapeHUD` card.
- Never mix legacy and kit components on one screen. A legacy component that the arcade comes to need is ported to
  UI Toolkit first, then moves into the kit.

## Build, check and publish

```sh
OUT=$(mktemp -d)
Tools~/web/build.sh "$OUT"                                   # also checks the output (see below)
python3 Tools~/web/harness.py "$OUT" Tokens~/tokens.json VbButton BattleHUD   # optional: renders into OUT/render/
```

`build.sh` fails when:

- a `vba` name is left;
- a legacy `vb-` class leaks into the kit;
- the bundle does not parse, or contains `</script` or `<!--`;
- a component is in the header without a README and preview;
- a `var(--…)` in the CSS is not a token or a property the CSS defines.

To publish, use the Artifact tool:

1. Read the artifact first. Then send one publish with `root` set to `OUT` and the `project/…` files.
2. Map the removed folders to `null`. These are the superseded legacy components without a kit name, and the old
   `Vb*` duplicates.
3. Pass `index.d.ts` as `text/plain`.
4. Upload new icons as assets (at most 25 per call) and list them in `assetGroups.Icons`.
5. Write `project/design-system.json` last. Keep `createdOnFiles`, and set `lastChange` with the source commit.

The sibling `veilbreak/design-system/` folder is a synced copy of the artifact. It picks up this structure on its next
resync. Do not edit it from here.
